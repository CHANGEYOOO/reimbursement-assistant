# 订单视觉识别测试版

这是一份独立安装的 Mac 测试版，基于正式版 1.34，测试版本 **1.34.909**。

## 怎么区分原版

| 项目 | 正式版 | 视觉测试版 |
| --- | --- | --- |
| 应用名称 | 报销单助手 | 报销单助手·视觉测试 |
| 图标 | 原报销单图标 | 橙色眼睛与 TEST 标记 |
| 窗口 | 正常界面 | 顶部常驻视觉测试提示 |
| 项目及缓存 | 原数据目录 | 独立的“报销单助手-视觉测试”目录 |
| 密钥和设置 | 原有配置 | 独立保存，需要重新填写 |

两者可以同时安装。测试版不读取或迁移正式版项目、API密钥、邮箱授权码，不参与正式版更新。Windows 和 GitHub 正式安装包不变。

## 开始测试

1. 打开测试 DMG，将“报销单助手·视觉测试”拖入“应用程序”，从这个名称打开。
2. 在设置的“AI 辅助识别”中重新填写服务商、接口、模型和密钥。**模型必须支持图片输入**，不要直接沿用纯文字型号。
3. 同时勾选“启用 AI 辅助识别”和“使用 AI 视觉识别订单截图（上传图片）”，点击“保存当前配置”。两项默认关闭。
4. 新建测试项目，导入少量订单截图。开启订单 AI 后，每张非重复的新截图只调用视觉 AI，不运行本地 OCR 和本地规则；关闭 AI 或截图上传选项时使用本地识别。
5. 看订单行内的“识别前”和“视觉结果”，对照右侧原图检查金额、日期和分类。各字段独立校验，合格结果会填入未手动修改的字段；金额不明确时先清空待定金额并提供有依据的候选，避免把待定金额当成确认结果。
6. 更换模型后，可以选中一行点击“重测选中订单”。这会再次请求API，可能再次收费。

“测试连接”只验证文字连接，成功不代表模型支持图片；图片是否支持以实际订单请求为准。接口失败会在订单行中说明，保持未识别字段为空，已有手动填写内容保留；不会自动使用本地规则或文字 AI 补填。

## 使用千问 AI 平台

服务商选择“千问 AI 平台”，填写在 platform.qianwenai.com 创建的密钥并保存。已预填完整接口地址与支持截图识别的 qwen3-vl-plus；模型名称也可自行修改。原阿里百炼的地址和密钥继续独立保留，不会自动挪用。

接口文档：[首次调用千问API](https://platform.qianwenai.com/docs/developer-guides/getting-started/first-api-call)；视觉模型：[视觉理解模型](https://platform.qianwenai.com/docs/developer-guides/getting-started/vision-models)。本次不使用用户密钥进行真实调用。

## 调整 AI 识别偏好

在“设置 → AI 辅助识别”中点击“AI 识别偏好…”。页面只保留选项和一个补充要求框：

- 用途选择简短概括，或保留商户名称。
- 日期选择是否允许用下单日期，以及只有月日时是否补当前年份。
- 所有个性化习惯统一写在“补充要求”，例如“用途尽量简短；设备租赁归其他”。

实付总金额、分类原则和结果格式由软件统一维护，无需编辑复杂规则。原有的分类补充和其他补充要求会合并进唯一的文本框，不会因升级丢失。旧版整段高级规则继续留存备份，但不再参与识别，避免多套规则互相冲突。

保存后仅用于后续识别，不会整批重新识别已有记录。“恢复默认设置”经确认后恢复选项并清空当前补充要求，旧高级规则备份保留。

用途优先采用 AI 对商品、转账备注、账单说明或交易商户的概括，例如“场地定金”“某便利店消费”“某平台消费”。不知道具体商品不等于无法概括用途，分类仍可以待分类；不凭付款渠道或平台标志猜测商品。手动修改和已保存重开的字段继续保留。

金额、日期、用途、分类分别校验。某字段返回格式不正确时，其他合格字段照常填入，失败字段保留原值并显示具体提示；金额确定值与候选冲突时供人工选择，日期冲突时保留原值。退款和收入仍不作为支出。

## 数据和费用

- 开启订单视觉上传后，仅发送**截图图像**，可能包含姓名、地址、账号、订单详情等信息。请求发往你自己配置的服务商。
- 图像会重新编码以移除原图元数据，长截图可按从上到下分段，在同一次请求内发送；超出安全尺寸或编码上限会提示，不静默漏掉截图内容。
- 同一条记录只自动尝试一次，失败也不会因为保存偏好而反复请求；重测需主动点击。切换识别模式不会整批重跑已完成记录。
- 已保存项目重开不会自动上传。重开后已有字段按保留值保护，主动重测仍会显示新视觉结果供比较，但不会覆盖这些字段。你在本次打开中手动修改的内容同样保留。
- 退款和收入不会作为确认支出填入；视觉金额不确定时仍需要人工选择或填写。
- 订单视觉上传和原有发票AI上传授权分别控制。只测试订单时，无需开启邮箱和发票AI。

真实服务商模型的识别效果、速度、费用和安装后的操作体验由你测试。本测试包仍使用本地签名，未进行 Apple 公证；首次打开可能出现系统安全提示。

交付验证：测试包1.34.909已完成 Release 编译、独立Bundle/名称/版本检查、本地签名验证及DMG完整性验证；原正式版1.34安装包字节未变。正式与测试身份断言、视觉引擎模拟请求、视觉字段保护及纯视觉模式独立回填检查均通过。正式编译分支的原有自动文字AI、金额日期证据与字段应用检查通过。

日期来源由模型根据截图判断；关闭使用下单日期时会通过识别要求约束模型，当前不提供独立的日期来源核验。真实模型仍可能识别错误。

如果在 AI 识别过程中删除记录，再撤销删除，该记录需要点击“重测选中订单”恢复识别，不会自动重发请求。

本版降低输出截断风险：视觉请求输出额度提高到4096 tokens，要求判断依据简短且不重复。对于官方 DeepSeek Flash 及其兼容旧名称，按[DeepSeek 参数文档](https://api-docs.deepseek.com/guides/thinking_mode/)关闭额外思考；其他接口和未知型号不添加该专用参数。截断、接口错误、网络错误均不自动重试，仅可手动点击重测。更高额度不保证模型永不截断，真实服务效果由用户测试。

金额以整笔订单的实付总金额为准，优先整单付款汇总中的最终实际支付总额，不使用单件商品或单晚价格、原价、优惠、运费等替代。已包含在总实付中的费用不再重复添加；没有明确唯一实付总额时提供候选，不自行推算。此口径随每次请求发送，无需手动维护。

本版改善返回格式兼容：对已确认支持的官方 DeepSeek Flash、千问视觉模型及部分千问系列启用 JSON Object 模式，按模型能力分别处理思考参数，不把 DeepSeek 参数发给千问。整单实付优先、用途语义总结、日期补年及4096输出额度等共用规则适用于两家。配置为其他兼容接口或未知型号时，不强加未经确认的专用参数。

本地可读取代码块包裹、首尾说明、BOM、文本块返回，以及不改变字段值的尾随逗号。遇到截断、重复字段、多个对象或真正损坏的内容，仍明确提示，不猜测金额或补全缺失内容。金额、日期、用途继续分别校验；解析不需要再次请求API，不会自动重试或另调模型修复。

参考：[DeepSeek JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)、[千问结构化输出](https://platform.qianwenai.com/docs/developer-guides/text-generation/structured-output)。离线模拟请求和格式异常检查用于验证程序兼容性，真实服务商的稳定性仍由用户安装后测试。

用途概括与商品分类分别判断。截图只有银行或平台的交易摘要时，可以写“某平台消费”等有依据的概括，即使分类仍为待分类；不凭付款渠道或平台标志猜测商品。DeepSeek 和千问均收到此共用要求。

如果 AI 已返回非空但不确定的用途，有商品、备注、账单或商户来源时会先填入待核对建议，不再直接清空；仍需人工核对后才能导出。不确定建议及原因会完整显示；来源未知时只展示建议，不自动填入。明确用途照常自动填入；手动填写及已保存的内容继续保护。不增加自动重试。

选择金额候选只解决金额相关提示，不会顺带确认仍待核对的用途建议；明确人工核对后才放行。
