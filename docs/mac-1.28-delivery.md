# Mac 1.28 交付说明

## 已实现

1. 报销项目列表固定按创建顺序排列，打开/选中不会重排。无变化保存不再改写文件或修改时间。原有项目 ID、JSON 结构、附件与关联关系保留。
2. 以左侧栏作为新建、打开和管理入口，移除顶部重复按钮及重复管理弹窗。侧栏项目提供原生右键打开、重命名和删除；删除确认明确说明订单和项目发票副本的影响。
3. 发票箱显示 PDF 第一页或图片实际内容缩略图，异步生成，有界缓存；未下载的历史附件只显示待下载占位，不因显示缩略图擅自下载。
4. 订单与发票使用共用 AttachmentPreview，在当前窗口中央按比例放大，再次点击主体、背景或 Esc 关闭，并支持来源位置动画和减少动态效果。PDF 翻页、触控板滚动/缩放独立处理；局部放大时首次点击先恢复适合窗口，避免误关。
5. 订单原有右侧预览栏的布局、宽度及功能保留；发票箱不新增常驻右侧附件预览栏。
6. 需要手动下载的发票邮件新增“查看邮件”，在可收起、可拖宽度的右侧栏展示发件人、主题、收件时间、正文和链接。切换邮件刷新内容，重复查看使用内存缓存。候选下载链接分别编号并显示网址，明确标为未经验证。
7. 邮件只读按需获取正文及有限的内嵌图片，不修改已读标记、邮件或发票归属。HTML 禁用脚本，并在 WebKit 远程资源拦截规则安装后加载，默认阻止远程图片、脚本、框架及网络请求。外部网址仅由用户主动点击后交给系统浏览器。
8. 设置新增“关于与更新”：读取应用版本及构建时现有 origin 仓库配置，从 GitHub 正式 Releases 检测更新，数值比较版本、匹配架构，显示更新日志与明确错误。仅主动点击下载，不静默安装。
9. 移除订单页手动 AI 识别按钮，自动 AI、已有 API 配置、金额/日期/用途规则保留。

当前代码中“项目”和“报销单”实际为同一 Draft 实体。本次统一入口，没有把不同数据对象强行合并，也没有创建新的业务层级。

## 主要文件与复用组件

- `ReviewView.swift`、`DraftStorage.swift`：稳定列表、无变化保存、侧栏管理和准确对象操作。
- `ImagePreview.swift`：共用 AttachmentPreview、窗口预览宿主、来源位置、比例及 PDFKit 浏览。
- `AttachmentThumbnail.swift`、`OrderPreviewPanel.swift`、`InvoiceInboxView.swift`：异步缩略图、原右栏接入、最新预览请求保护。
- `QQMailbox.swift`、`QQMailboxParser.swift`、`MailDetailView.swift`：按需 MIME 正文、只读 IMAP、安全 HTML、可调整邮件侧栏。
- `GitHubUpdates.swift`、`AboutUpdatesView.swift`、`AppSettingsView.swift`：版本判断、安装包匹配及原生设置页。
- 原有自动 AI、缓存管理和发票业务模块继续复用；预览中的发票缓存会标记为正在使用，关闭后恢复正常缓存维护。

## 需要人工验收

请在安装后重点检查：连续切换项目不跳位；右键菜单作用于点击对象；图片/PDF 点击放大返回、Esc、背景、翻页和触控板手势；窗口缩放；邮件详情展开/收起及真实邮件排版；正文链接打开；设置中的检查更新。

本次未把完整真实 GUI、真实 QQ 邮箱及鼠标/触控板操作当作已验收通过。没有已知编译或离线检查阻断项。

## 已知限制

- 邮件详情仅针对现有 QQ 收件箱同步中保留的邮件记录。正文最大2 MB，单张内嵌图片最大512 KB、合计2 MB；正文缓存最多8封。远程图片默认不加载，部分邮件排版或图片可能与邮箱网页不同。
- 保留现有图片、PDF、ZIP 导入范围；未新增 OFD/XML 导入或解析能力，不可渲染的附件使用类型占位。
- 缩略图缓存最多128项。放大预览使用原文件而非低清晰度缩略图。
- 创建顺序使用本地文件夹创建时间；把项目目录复制到新磁盘时，文件系统创建时间可能改变。
- 若旧 GitHub 安装包名称未明确标注架构，则转到发布页面，由用户确认兼容性后下载，不猜测兼容性。
- 安装包沿用本地签名，未新增 Apple 公证流程。本次尚未创建 GitHub 正式发布。

Windows 开发已暂停，既有代码完整保留在 `codex/windows-mac127-parity`；此次 Mac 修改在独立工作区和分支进行。
